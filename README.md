# 재고·순이익 관리 시스템 — 설정 가이드

매일 매출/원물입고/출하/폐기/박스입출고/택배비를 휴대폰 폼([input.html](input.html))으로 입력하면,
[index.html](index.html) 대시보드에서 자동으로 재고와 순이익을 시각화해서 보여줍니다.
품목 마스터는 [items.html](items.html), 이모님 인건비는 [labor.html](labor.html)에서 관리합니다.

데이터는 Supabase(무료 클라우드 DB)에 저장되고, 이 폴더 자체를 GitHub Pages로 올려서
휴대폰에서 URL로 바로 접속하는 구조입니다.

## 1. Supabase 프로젝트 만들기
1. [supabase.com](https://supabase.com) 에서 무료 계정을 만듭니다.
2. **New Project**로 새 프로젝트를 생성합니다 (이름은 아무거나, 예: `재고관리`). DB 비밀번호는 잘 보관하세요.
3. 왼쪽 메뉴 **SQL Editor** 클릭 → **New query** → 이 폴더의 [db/schema.sql](db/schema.sql) 내용 전체를
   복사해 붙여넣고 **Run** 버튼을 누릅니다. 에러 없이 끝나면 완료입니다.
4. 왼쪽 메뉴 **Project Settings > API**로 이동해서 다음 두 값을 확인합니다.
   - **Project URL**
   - **anon public** 키 (secret/service_role 키는 사용하지 않습니다)
5. 이 두 값을 저에게 알려주시면 [config.js](config.js)에 채워드립니다. (직접 채우셔도 됩니다 — 파일 열어서
   `YOUR_SUPABASE_PROJECT_URL`, `YOUR_SUPABASE_ANON_KEY` 부분만 바꾸면 됩니다.)

## 2. 품목 등록 (선택, 나중에 웹에서 추가해도 됨)
자주 쓰는 원물/박스/부자재(포장재·소모품 등) 품목은 [items.html](items.html)에서 카테고리별로
등록·수정·비활성화할 수 있고, 추가할 때 지금 창고에 있는 초기 재고 수량도 바로 입력할 수 있습니다.
나중에 재고가 실제와 안 맞으면 품목 수정 화면의 "현재 재고 수량" 칸을 원하는 값으로 고쳐서 저장하면
그 차이만큼 자동으로 조정 기록이 남습니다. [input.html](input.html)에서 입력하다가 "+ 새 품목 추가"로
그때그때 추가해도 됩니다.

### 스키마가 이미 한 번 설정되어 있다면 (업데이트)
기능이 추가될 때마다 `db/schema.sql`이 갱신됩니다. Supabase **SQL Editor**에 전체 내용을 다시 붙여넣고
**Run** 하면 됩니다 — `create table if not exists` / `create or replace view`로 되어 있어서 여러 번
실행해도 기존 데이터는 그대로 유지되고 새로 추가된 테이블/뷰만 반영됩니다.

## 3. 휴대폰에서 쓸 수 있게 배포하기 (GitHub Pages)
1. [github.com](https://github.com) 에서 무료 계정을 만듭니다 (이미 있으면 생략).
2. 새 저장소(Repository)를 만듭니다 (Public 또는 Private 모두 가능, 이름은 아무거나, 예: `jaego`).
3. 이 폴더를 그 저장소에 push합니다. (git이 처음이시면 말씀해주시면 명령어를 대신 실행해드릴 수 있습니다.)
4. 저장소 **Settings > Pages**에서 **Source**를 `main` 브랜치, `/ (root)`로 설정하고 저장합니다.
5. 몇 분 뒤 `https://<계정이름>.github.io/<저장소이름>/` 형태의 URL이 생깁니다. 이 주소를 휴대폰 홈 화면에
   추가해두면 앱처럼 바로 열 수 있습니다. `input.html`이 매일 입력용, `index.html`이 대시보드입니다.

## 4. 사용법
- 매일 [input.html](input.html)을 열어 그날의 매출/택배비/원물입고/출하/폐기/박스입출고를 입력합니다.
  항목별로 각각 "저장" 버튼을 누르면 바로 반영됩니다. 여러 품목을 입력할 땐 같은 섹션에서 반복해서
  저장하면 됩니다. 맨 아래 "이 날짜에 입력한 내역"에서 잘못 입력한 걸 ✏️(수정)·🗑️(삭제)로 바로 고칠 수
  있습니다 — 날짜를 바꾸면 그 날짜의 내역도 똑같이 관리할 수 있습니다.
- [items.html](items.html)에서 원물/박스/부자재 품목을 카테고리 탭으로 나눠서 추가·수정하고, 재고 수량도
  직접 맞출 수 있습니다. 중량·상품별 택배비·포장비·기타비용·매입처와 "택배비 구간표"도 여기서 관리합니다.
- [shipments.html](shipments.html)에서 매일 어드민 주문양식 → CJ택배 다운로드양식 순서로 업로드하면
  품목별 출고량과 실제 택배비가 자동으로 집계·반영됩니다 (아래 "택배 파일 매일 업로드" 참고).
- [labor.html](labor.html)에서 이모님 등 일당제 근무자를 등록하고, 오늘 출근한 사람을 체크만 하면
  자동으로 근무기록이 쌓입니다. 월별 캘린더에서 근무자별 근무일수·지급액을 한눈에 확인할 수 있습니다.
- [index.html](index.html) 대시보드에서 오늘 매출/순이익(비용 항목별 내역 포함), 기간별(오늘/어제/최근
  7일/최근 30일 또는 직접 선택한 기간) 순이익, 원물·박스·부자재 재고 현황, 최근 30일 추이, 폐기 내역을
  확인하고, "지금 내보내기" 버튼으로 구글시트에 백업할 수 있습니다.

## 5. 택배 파일 매일 업로드 ([shipments.html](shipments.html))
1. **① 어드민 주문양식**을 그날 다운로드한 그대로 업로드합니다. 파일에 날짜가 없어서 "출고 기준일"을
   직접 골라주세요(기본값 오늘). 상품명이 처음 보는 표기면 "매칭 확인"에 미매칭으로 뜨는데, 어느 품목인지
   드롭다운에서 골라주시면 됩니다 — 한 번 골라두면 다음부터는 자동으로 인식됩니다. **저장**을 누르면 원물
   재고와 출하 기록에 자동 반영됩니다.
2. **② CJ택배 다운로드양식**을 그 다음에 업로드합니다. ①에서 등록된 주문과 운송장번호로 매칭해서 실제
   택배비를 채워 넣고, ①에 없던 주문(벤더가 직접 배송한 것 등)은 새로 등록합니다.
3. 아래 "출고 집계"에서 기간을 골라 품목별 출고량·총 택배비를 바로 확인할 수 있습니다.
4. 같은 파일을 실수로 두 번 올려도 주문번호/운송장번호 기준으로 중복 저장되지 않습니다.

## 6. 구글시트 연동 (수동 "지금 내보내기" 버튼)
서버 없이 사장님 구글 계정으로 직접 로그인해서 시트에 쓰는 방식이라, Google Cloud Console에서 OAuth
클라이언트 ID를 한 번만 만들어두면 됩니다.

1. [console.cloud.google.com](https://console.cloud.google.com) 접속 → 새 프로젝트 생성 (이름 아무거나).
2. 왼쪽 메뉴 **API 및 서비스 > 라이브러리**에서 "Google Sheets API" 검색 → **사용 설정**.
3. **API 및 서비스 > OAuth 동의 화면**에서 "외부" 선택 → 앱 이름/이메일만 채우고 저장 (테스트 사용자에
   본인 구글 계정 이메일 추가).
4. **API 및 서비스 > 사용자 인증 정보 > 사용자 인증 정보 만들기 > OAuth 클라이언트 ID** → 애플리케이션
   유형 **웹 애플리케이션** → "승인된 자바스크립트 원본"에 GitHub Pages 주소
   (`https://<계정이름>.github.io`, 끝에 슬래시나 경로 없이)를 추가 → 만들기.
5. 생성된 **클라이언트 ID**를 복사합니다.
6. [Google 스프레드시트](https://sheets.new)를 하나 새로 만들고, 주소창의 `.../d/`와 `/edit` 사이에 있는
   긴 문자열이 **스프레드시트 ID**입니다.
7. 클라이언트 ID와 스프레드시트 ID를 [config.js](config.js)의 `GOOGLE_CONFIG`에 채워주세요 (또는 저에게
   알려주시면 대신 채워드립니다).
8. 대시보드에서 "지금 내보내기"를 누르면 구글 로그인 창이 뜨고, 승인하면 그 달 이름의 탭(예: `2026-08`)에
   매출/비용/순이익과 품목별 출고 집계가 저장됩니다. 몇 번을 눌러도 그 시점 최신 데이터로 덮어써서
   중복되지 않습니다.

## 순이익 계산 방식
```
순이익 = 매출 − 원물출하원가 − 박스비 − 부자재비 − 포장비 − 상품기타비용
        − 폐기손실 − 택배비 − 인건비 − 기타비용
```
- 원물출하원가/박스비/부자재비: `출하`로 기록한 수량 × 품목 매입단가 (카테고리별로 구분)
- 포장비/상품기타비용: `출하`로 기록한 수량 × 품목에 등록한 포장비/기타비용 (items.html에서 설정)
- 폐기손실: `폐기`로 기록한 수량 × 품목 매입단가
- 택배비: input.html에서 수기 입력한 금액 + shipments.html 업로드로 쌓인 실제/추정 택배비 합계
- 기타비용: input.html의 "택배비/기타비용" 중 "기타" 항목
- 인건비: labor.html에서 체크한 그날 근무자들의 지급액 합계

품목별 택배비는 items.html에 등록한 "상품별 택배비"가 있으면 그걸 쓰고, 없으면 등록된 중량 기준으로
"택배비 구간표"에서 자동으로 찾아 적용합니다. CJ 파일에 실제 청구된 택배비가 있으면 그 값이 우선합니다.

## 보안 참고
`config.js`의 anon key는 브라우저에 그대로 노출됩니다. Supabase에 RLS(행 단위 보안)를 켜두긴 했지만
지금은 "누구나 읽기/쓰기 허용" 정책이라, 이 URL을 아는 사람은 데이터를 보거나 바꿀 수 있습니다. 지금은
URL을 남에게 공유하지 않는 것으로 충분하지만, 나중에 더 안전하게 하고 싶으시면 Supabase Auth(이메일
로그인)를 추가할 수 있습니다 — 필요하시면 말씀해주세요.

## 다음 단계 (보류 중, 원하시면 나중에 진행)
- **AI 채팅 입력/질의**: "오늘 대저토마토 30박스 출고했어" 같은 문장으로 데이터를 넣거나 "이번 달 매출
  얼마야?" 같은 질문에 답하는 기능. 지금 구조(정적 페이지 + Supabase)로는 안 되고, AI API 키를 안전하게
  보관할 서버가 하나 필요합니다. 사용량에 따른 비용도 발생합니다.
- **카카오톡 연동**: 개인 단톡방은 외부 프로그램이 읽을 수 있는 공식 API가 없어서 그대로는 불가능하고,
  카카오톡 채널(비즈니스 계정) 챗봇 API를 통해서만 가능합니다 — 별도 사업자 심사가 필요합니다.
- 매출(판매금액) 정보가 담긴 정산 파일이 따로 생기면, 그것도 자동 집계에 포함시킬 수 있습니다.
